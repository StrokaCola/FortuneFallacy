# FortuneFallacy — QA Report

**Date:** 2026-05-12
**Branch:** `claude/game-testing-qa-UTD0I` (65 commits ahead of main; recent work concentrated on Forge UI + dice VFX)
**Tester scope:** Functional bugs, design-feel issues, UX/polish. No live browser playthrough — see Methodology.

---

## Summary

Five things to look at first, in order of severity:

1. **[CRITICAL]** Chain cap default mismatch. Two files disagree on the cap (4 vs 8). Runtime uses 8; the unit test and balance simulator both assume 4. The 2026-05-07 audit comment claims chain cap was lowered to 4 — that lowering never reached the runtime path. (`core/run/diceContext.ts:10` vs `core/scoring/constellationChain.ts:6`)
2. **[CRITICAL]** Three legendary catalysts are unreachable. `eclipse_pact`, `heirloom_locket`, `recursion_lens` are fully implemented (data, upgrades, audio) but no code path ever grants their unlock. Only `legendary_all_band` is granted. (`core/shop/catalystDraw.ts:8`, `actions/handlers/shop.ts:57`, `actions/handlers/catalyst.ts:9`)
3. **[HIGH]** Mirrored Hand easter egg is mathematically impossible. Zero of the 86 catalyst names are palindromes; the trigger condition can never be met. (`data/easterEggs.ts:64`, `core/round/scalingHooks.ts:228`)
4. **[HIGH]** Stake-difficulty cliff. Per the balance simulator at the "scaling" build profile on Lyra, any-clear rates drop Spark 88% → Ember 51% → Pyre 51% → **Beacon 15% → Nova 12% → Supernova 9%**. The top three stakes are effectively unwinnable for non-synergy builds, yet `stake_beacon/nova/supernova` achievements exist.
5. **[HIGH]** Constellation parity is broken. At Spark/scaling A4, Argo clears 12%, Polyhedra 22%, Triumvirate 24% vs Lyra 82%. Fibonacci over-clears at 93%. The sim explicitly flags 59–71pp gaps.

## Critical bugs

### C1. Chain-cap default mismatch — runtime ≠ test ≠ sim
**File:** `src-next/core/run/diceContext.ts:10` and `src-next/core/scoring/constellationChain.ts:6`

```
diceContext.ts:10        const CHAIN_CAP_DEFAULT = 8;
constellationChain.ts:6  const CHAIN_MAX_DEFAULT = 4;
```

`scoring.ts` always passes `getChainConfig(state)` to `applyChain`, which always returns `cap: 8`. The `CHAIN_MAX_DEFAULT = 4` fallback in `constellationChain.ts` is **dead code** — `config.cap` is always set when the engine calls it. But `constellationChain.test.ts:30` asserts "caps at 4 (default)" and the full-run sim at `balance.fullrun.sim.test.ts:178` uses `cap = mods.chainCap ?? 4`. **The simulator and the unit test do not model live gameplay.**

A header comment in `constellationChain.ts:1-6` explicitly states chain cap was "Lowered 8 → 4 per the 2026-05-07 audit" — so this is a half-finished audit change. Worse: Ophiuchus had `chainCap: 4` removed because it was "redundant with the new default" — but the new default never went live, so Ophiuchus actually got an unannounced buff (it was lowering cap to 4 when runtime is 8).

**Suggested fix:** Decide whether the design intent is cap=4 or cap=8. If 4, change `CHAIN_CAP_DEFAULT` in `diceContext.ts` to 4 and re-run sims. If 8, update the unit test, the sim, the comment, and rethink Ophiuchus's identity penalty.

### C2. Three of four legendary catalysts are unreachable
**Files:** `src-next/data/catalysts.ts:130,227,318,347` (legendaries); `src-next/core/shop/catalystDraw.ts:8` (gate); `src-next/actions/handlers/shop.ts:57` and `src-next/actions/handlers/catalyst.ts:9` (only `legendary_all_band` is ever added to `meta.unlocks`).

`isLegendaryUnlocked` returns false for any legendary whose `legendary_<id>` is not in `meta.unlocks`. A repo-wide grep for the prefix shows **`legendary_all_band` is the only string ever added**. `eclipse_pact`, `heirloom_locket`, `recursion_lens` have full implementations in `core/upgrades/catalysts/`, `audio/listeners/scalingSfx.ts`, `state/slices/run.ts` etc., but the shop never offers them.

The catalystDraw test asserts only that `all_band` is locked when missing — there is no test that the other three are reachable, because they can't be.

**Suggested fix:** Either (a) define unlock conditions and grant points for the other three legendaries, or (b) make them unlocked-by-default (drop from the gate, or whitelist them in `SEEDED_UNLOCKS`). Today they're a black hole of effort.

### C3. Mirrored Hand easter egg is unreachable
**Files:** `src-next/data/easterEggs.ts:64`, `src-next/core/round/scalingHooks.ts:228`, `src-next/core/round/transitions.ts:90`

Trigger: hold ≥2 owned catalysts whose `name` is a palindrome (case-insensitive, letters-only). Scanning all 86 entries in `CATALYST_META`, **zero names are palindromes** (`Tempo`, `Apex`, `Audit`, `Stutter`, `Tetrad` etc. are all non-palindromic). Confirmed:

```
$ node -e "/* isPalindrome over all 86 names */"
Palindromic names: []
```

The egg is also wired into `RETRIGGER_CATALYST_IDS` and `SCALING_NOTE_IDX` for audio, so dead content has dead audio support attached.

**Suggested fix:** Either rename two catalysts to palindromes (e.g. `Apex` → `Ada`, or add a `Solos`-style name), broaden the predicate (e.g. "names that are anagrams of each other"), or pick a different hidden condition. Worth checking whether achievement `misc_legendary_fire` or any other check also keys off this egg.

## Functional bugs

### F1. Wildcard resolution is greedy and provably suboptimal
**File:** `src-next/core/phases/evaluation.ts:24-40`

`resolveWildcards` assigns each wildcard one at a time, picking the value that maximizes tier *given the current working set*. The comment claims "greedy is sufficient … combo tiers are monotonic in matches" — but it isn't, because straights need a *coordinated* assignment.

Counter-example. Ophiuchus dice rolled `[3, 4, WILD, WILD, 2]`, universe `[1,2,3,4,5]`:
- Iteration 1 — try each v: best tier is `v=3` or `v=4` (one pair, tier 1). Greedy picks `v=3`.
- Iteration 2 — best is `v=3` (three of a kind, tier 3).
- Final hand: `[3,4,3,3,2]`, tier 3.

Optimal assignment: `v=5, v=1` (or `v=1, v=5`) → `[3,4,5,1,2]`, **small straight, tier 4**. Greedy misses one tier.

This matters in roughly 1-in-6 Ophiuchus hands (any hand with 2+ wildcards) and any hand using Wildcard mod. Same suboptimal logic is duplicated in the balance sim at `balance.fullrun.sim.test.ts:90-111`, so even the sim under-estimates Ophiuchus.

**Suggested fix:** For ≤2 wildcards, exhaustive search over `universe.length²` is cheap (≤36 candidates). For ≥3 wildcards, brute force is still tiny (≤6³=216). Replace the for-loop with a full enumeration over wildcard assignments.

### F2. Stale doc comment for `baseChipsMult` in ConstellationModifiers
**File:** `src-next/data/constellations.ts:26-27`

```
baseChipsMult?: number;  // multiply combo base chips (Eclipse 0.25)
baseMultMult?: number;   // multiply combo base mult (Eclipse 0.25)
```

Eclipse is actually `0.5` (line 159) and Ophiuchus is also `0.5` (line 195). The comment is outdated. Low impact but misleading the next contributor.

### F3. The Forge layout system fights itself
**File:** `src-next/app/screens/Forge.tsx`

The last 65 commits are almost entirely tweaks fighting the Forge's mixed React/WebGL layout: stale cube rects after selection swaps (`Forge.tsx:113-128`), die canvas competing for z-order with backdrop-filter panels (`Forge.tsx:135-144`), positioning shims biasing rects, etc. The current code works, but the *architecture* (shared canvas overlayed on React placeholders) is brittle — any new sticky pane or backdrop-filter risks repainting the bug.

**Suggested fix:** Not a bug to fix today, but flag as tech debt. A single canvas-per-die approach (or HTML-only dice with CSS 3D transforms for the Forge) would eliminate the rect-invalidation dance.

## Design / feel issues — underwhelming or trivial

### D1. Stake ladder has a cliff between Pyre and Beacon
Sim numbers (Lyra / scaling build / Spark→Supernova):

```
spark        88% any-clear,  82% A4
ember        51%,             14% A4
pyre         51%,             15% A4
beacon       15%,              0% A4   ← cliff
nova         12%,              0% A4
supernova     9%,              0% A4
```

Beacon, Nova, and Supernova are 0% A4 at the "scaling" profile (sim's mid-game player model). Only the "synergy" profile (cap 40× total mult) ever clears them. This means:

- The `stake_beacon`, `stake_nova`, `stake_supernova` achievements are gated behind near-perfect builds.
- The daily challenge rotation puts a Beacon daily once a week (`dailyChallenge.ts:73`) — most players will never finish a Beacon daily.
- Progression-wise, players hit a brick wall once they "graduate" past Pyre.

**Suggested fix:** Either flatten the Beacon→Supernova handsDelta/targetMult curve (currently a 4-hand budget on Spark vs 2-hand on Beacon), or surface stake-difficulty more honestly in the Hub picker.

### D2. Constellation parity broken — Argo, Polyhedra, Triumvirate noticeably weaker
At Spark / scaling profile (sim), A4 clear rates:

```
fibonacci    93%
lyra         82%
mensa        69%
eclipse      71%
ophiuchus    67%
triumvirate  24%   ← -58pp vs lyra
polyhedra    22%   ← -60pp vs lyra
argo         12%   ← -70pp vs lyra
```

The sim's own outlier-flag rule (Δ > 25pp from Lyra) flags all three. Argo just received a balance pass (perCat 0.75→1.0, seed Captain's Wage) but the sim still puts it dead last. Triumvirate's 3-d12 "few hands big numbers" identity doesn't translate to enough volume. Polyhedra's heterogeneous dice rarely line up for combos.

Fibonacci on the other hand over-clears (93% vs 82% baseline). The [1,1,2,3,5,8] face distribution makes pairs trivial and the 8 carries chips.

**Suggested fix:** Per-constellation tuning rather than uniform buffs. Argo needs another bump (slot bonus or a free reroll). Polyhedra wants either a cross-shape synergy bonus or a face-universe normalization. Fibonacci could lose 1 die or have its 8s capped.

### D3. Ophiuchus has no identity penalty anymore
**File:** `src-next/data/constellations.ts:192-195`

Code comment explicitly states: "chainCap: 4 was Ophiuchus's punishment but matches the new default… removed as identity. Constellation may want a fresh drawback to maintain its high-risk identity; flagged in audit."

Combined with C1, Ophiuchus is now strictly safer than intended:
- Rules card still says "Base chips & mult ×0.5 (WILD-driven combos hit hard already)" — the player reads this as a stiff penalty.
- Wildcards trivialize combo detection.
- The "compensating" chain cap restriction never existed in the live runtime.

Ophiuchus currently lands at 67% A4 (in the middle of the pack) and feels fine in the sim, but the rules-vs-reality gap is real.

### D4. Awakening is "purely cosmetic"
**File:** `src-next/data/catalysts.ts:386-408`

`AWAKENING_THRESHOLDS` is defined for 14 catalysts with the comment: "v1 is purely cosmetic; mechanical scaling will follow once playtesting confirms the right multipliers per archetype." So the player sees a "★ Awakened" badge but it does nothing. This is the kind of half-implemented hype-feature that disappoints when the player figures it out.

**Suggested fix:** Either ship a mechanical reward (even a token +1 chip or +0.5 mult per awakening) or remove the badge until the mechanic ships.

### D5. Risk mod is a trap pick on Eclipse and Ophiuchus
**File:** `src-next/core/mods/index.ts:312-317`

Risk: `+6 mult on face 6, -3 mult on face 1`.

- Eclipse dice are `[0,0,0,1,1,1]`. Face 6 never rolls; face 1 rolls 50%. Risk yields **-1.5 mult average per scoring die** — strictly negative.
- Ophiuchus dice are `[1,2,3,4,5,WILD]`. Face 6 doesn't exist in the universe (wildcards substitute up to 5). Face 1 rolls 1/6. Risk yields **-0.5 mult average** — strictly negative.
- Triumvirate (d12): face 6 = 1/12 (+0.5 mult), face 1 = 1/12 (-0.25 mult). Net +0.25 — underwhelming compared to a baseline mod.

There's no warning when offered; the player just learns to avoid Risk on these constellations the hard way.

**Suggested fix:** Gate Risk out of the shop pool when the constellation's `faceUniverse` lacks 6, *or* make the penalty/payoff face-universe-aware (e.g. min and max face of the universe). Same logic applies to Snake Eyes, Crown, Iron Six, Six Bias, Solar Flare, High Roller — all key off face 6 specifically.

### D6. Eris vs Callisto — boss power is uneven
**File:** `src-next/data/blinds.ts:225-251`

- **Callisto**: `disable_catalysts` — catalysts inert the entire boss blind.
- **Eris**: `disable_catalysts_first_hand` — catalysts inert hand 1 only.

These are the same debuff at very different strengths. Callisto is brutal (potentially run-ending for catalyst-heavy builds); Eris is a mild speed-bump. With both rolled uniformly via `pickBoss(rng)`, the player has a flat 1-in-8 chance of getting the run-ender Callisto and 1-in-8 of getting the harmless Eris.

**Suggested fix:** Either bring Eris in line (e.g. "disable catalysts for the first 2 hands" or "catalysts cost 1 shard each to fire") or weaken Callisto to "catalyst chips/mult ×0.5".

### D7. Shard economy actively punishes overscoring
**File:** `src-next/data/balance.shards.sim.test.ts`

Sim output:
```
profile                              legacy      new  delta
tight   (3 hands, just clears)          144      202  +58
average (2 hands used)                  144      228  +84
lucky   (1-hand clear, big score)       521      255  -266
high-roll (1-hand, 4× target)           622      255  -367
```

Under the new shard curve, players who clear blinds in one hand with big scores earn **less** money than players who scrape by. This inverts the natural "play well → buy more catalysts → snowball" loop. A high-roller's reward is shaved by 60%.

**Suggested fix:** Add an overscore bonus (10-20% of the overflow as bonus shards), so committing to a high-mult build still pays.

### D8. "Sixth Star" voucher dominates other vouchers
**File:** `src-next/data/vouchers.ts:24`

+1 die for 12 shards is the biggest single power swing in the game — for 3-dice constellations (Argo, Triumvirate) it's a +33% dice count. The comment in code even calls this out. Compared to:
- Bench: +1 catalyst slot (8 shards) — usually less impactful
- Forged Links: +1 mod slot per die (8 shards) — strong but conditional on attaching mods
- Shard Streak: +1 shard per trial (6 shards) — pays back ~12 shards over a run, just barely positive

The voucher shop becomes "Sixth Star or nothing" once you can afford it.

**Suggested fix:** Raise Sixth Star to 18-20 shards, OR convert it to a constellation-specific upgrade with diminishing value (e.g. doesn't stack for 5+ dice constellations).

### D9. Lucky Seven easter egg is hard-locked by constellation
**File:** `src-next/data/easterEggs.ts:50-55`

Requires "score 3+ scoring 7s in one hand." Face 7 only exists on d8 / d10 / d12 dice.

- Lyra, Mensa, Eclipse, Ophiuchus, Fibonacci: face universe has no 7. Egg **impossible** on 5 of 8 constellations.
- Polyhedra: has d8/d10/d12 — exactly 3 sources of 7. P ≈ (1/8)(1/10)(1/12) ≈ 0.1% per hand.
- Triumvirate (3 d12s): all three need to roll 7. P ≈ 0.058%.
- Argo (3 d20s): P ≈ 0.0125%.

It's reachable but extremely rare on the 3 constellations where it works. Not a bug; just very hidden. Players on Lyra (the default constellation!) literally cannot find this egg in normal play. Worth a hint pointing at constellation choice.

### D10. Pi easter egg is gated by face universe
**File:** `src-next/data/easterEggs.ts:43-47`

Requires "first three dice settle 3-1-4 (in order) on the first roll." Face 4 doesn't exist on Fibonacci `[1,1,2,3,5,8]` or Eclipse `[0,0,0,1,1,1]`. Egg is **impossible** on those two constellations.

## UX & polish

### U1. Sell button under-sized for touch (WCAG 2.5.5)
**File:** `src-next/styles/index.css:225-245`

```
min-width: 28px; min-height: 22px;   /* visual chip */
@media (hover: none) { padding: 10px 12px }   /* touch extension */
```

After padding: 22+20=**42px tall**, 28+24=52px wide. WCAG 2.5.5 wants 44×44. The code comment claims compliance but the math is short by 2px on the vertical. Minor but visible on small phones.

### U2. `user-scalable=no` blocks pinch-zoom
**File:** `index.html:5`

Mobile users with low vision can't pinch-zoom to read small text. WCAG 1.4.4 requires text to be resizable to 200% without loss of functionality. For a game that's mobile-first and has lots of small chip/mult readouts, this is a real accessibility gap.

**Suggested fix:** Drop `user-scalable=no` and set CSS to prevent layout breakage at 200% zoom. Most modern mobile games leave zoom enabled.

### U3. Beacon daily-challenge rotation creates dead days
**File:** `src-next/online/dailyChallenge.ts:73`

1-in-7 days the rotation lands on Beacon. Per the balance sim, Beacon scaling-profile clear is 15%. Most players cannot finish a Beacon daily, so 1 in 7 dailies effectively yields no leaderboard activity from the mid-tier audience.

**Suggested fix:** Replace Beacon with Pyre in the ladder, or cap dailies at Pyre and add a separate "Hard Daily" track.

### U4. Audio support exists for dead content
**File:** `src-next/audio/listeners/scalingSfx.ts:37,52,55`

`SCALING_NOTE_IDX` entries for `heirloom_locket` and `RETRIGGER_NOTE_IDX` entries for `recursion_lens` are wired but those catalysts never spawn (see C2). Cosmetic dead code; will become live the moment C2 is fixed.

## Suggestions (cheap wins)

- **Fix C1 (chain cap)** — one constant change in `diceContext.ts`. Pick 4 or 8, align test/sim/runtime.
- **Fix C2 (legendaries)** — add 3 strings to a default-unlocks list, or three `meta.unlocks` grants in the right handler. Unlocks 3 catalysts worth of content for free.
- **Fix C3 (mirrored hand egg)** — rename one or two catalysts to palindromes. Suggestions: "Apex" → "Ada", "Audit" → "Anna", "Tempo" → "Solos". Small data edits.
- **Rename or balance Risk on face-bare constellations** — soft-gate in the shop draw.
- **Strip the Awakening badge or ship its mechanic** — the cosmetic-only state is worse than not shipping the feature yet.
- **Drop `user-scalable=no`** — single attribute, large accessibility win.
- **Add a sim test for legendary reachability** — assert at least one of each legendary is drawable given a fully-unlocked meta.
- **Add a sim test that runtime chain cap matches `applyChain` cap** — would have caught C1 immediately.

## Methodology & caveats

This was a **static + simulation** QA pass, not a live playthrough. I:

- Read scoring (`core/scoring/`, `core/phases/`), shop (`core/shop/`), mods (`core/mods/`), constellations, blinds, stakes, vouchers, achievements, easter eggs, daily challenge, and recent commit diffs end-to-end.
- Used the existing balance simulators (`data/balance.*.sim.test.ts`) — they already model full runs across 8 constellations × 6 stakes × 4 build profiles × 200 runs/cell. I read their output rather than re-running them blindly.
- Hand-traced the wildcard resolver, chain-cap path, legendary unlock gate, and palindrome easter egg over the actual content data.

**What I could not test:**
- Visual VFX / animation quality of recent Forge work (no live browser driver)
- Touch interactions, gesture handling, haptics on real devices
- Real audio mixing (jsdom doesn't render canvas/audio)
- Multiplayer / leaderboard submission paths
- Frame-perfect timing bugs in animation/SFX scheduling

The QA findings above are grounded in code references; the "underwhelming/trivial" claims are grounded in either sim output, content data, or arithmetic over face universes. Anywhere I make a claim, I cite a `file:line` so it's verifiable.
